REVIEW + RELEASE NOTES · 24 OCTOBER 2026

A stronger programme.
A calmer gym experience.

Reviewed source: Phase_3_Revised_Interactive_iPhone_PWA.zip. This report distinguishes observed interface behaviour and source-code findings from training-design recommendations.

What worked

The original had a recognisable editorial identity, individual day colours, a useful weekly split, stationary alternatives and no dependency on paid fitness services. Those foundations remain. The revised edition keeps the bold typography while using dark text on lighter day colours for readability.

Critique and changes

  1. Opening the week: the large repeated header used valuable workout space; week selection and the four-session priority were unclear. The new dashboard makes the selected week explicit, gives a direct training action and separates optional/reset days from strength-session completion.
  2. Recording a set: the original SAVE SETS action rerendered the entire workout with blank fields, risking loss of other unsubmitted entries. The new inputs save individually without rerendering. Left and right repetitions are recorded separately, and unfinished sets are not silently counted as completed.
  3. Changing an exercise: alternatives were labels, not actionable prescriptions. Every slot now has a selectable alternative with its own equipment, rep/time range, guidance and independent log. Preferred choices can be saved for future sessions. Prior loads from another exercise are never copied across.
  4. Viewing movement guidance: generic drawings reused an overhead press or pull pattern for unrelated exercises and could mislead. They have been removed. All variations now have setup/move/finish coaching cards. Cable pull-through retains an exercise-specific interactive side-view schematic. Other movements are intentionally not represented by fabricated anatomical demonstrations.
  5. Completing a session: a blanket completion toggle gave no indication of missing sets. The new flow distinguishes a completed partial workout from a fully ticked session and permits reopening for corrections.
  6. Reviewing progress: the old screen showed counts and a mistaken Phase 02 label, rather than useful lifting history. The replacement includes per-exercise history, load bars, dates, left/right values and block/week identity. Different variations are not treated as equivalent loads.
  7. Eight-week progression: the old plan only described a deload; cards did not change. The revised cards apply week-specific effort and reduced deload sets. A new block retains old records. The false implication that the static site automatically receives a newly generated programme has been removed.
  8. Protecting records: the original import validation was too loose and immediately replaced data. New imports validate structure and numbers, then require a deliberate replace action with an export option. Old-format records are preserved as an archive instead of being inaccurately mapped to new exercises. Storage errors are surfaced.

Training refinements

Friday’s landmine press was paired with a dumbbell equipment label. It is now a supported seated dumbbell press with a machine-press alternative. A reverse pec deck was not a close enough substitute for the primary row; the row alternative is now another row.

Wednesday is now genuinely easy and unweighted. Sunday is optional, shorter and avoids an additional demanding leg session before Monday. The split squat is supported and stationary. Redundant accessories were reduced, while weighted hip hinges and Monday’s direct hip-flexor work remain.

All strength movements have clear rest and effort targets. Full-session time estimates are honest about unilateral work; Express provides a practical short option rather than encouraging rushed rest. No kilograms are prescribed without a baseline.

The focus on repeatable, manageable training is consistent with ACSM’s emphasis on regular participation. This is a general fitness plan and does not establish that any exercise is suitable for an individual injury.

New features included

  • Autosaved load, reps/time, RIR, left/right entries and set ticks.
  • Full and Express workouts with collapsed exercise cards.
  • Selectable alternatives and saved preferred swaps.
  • Previous same-variation loads; copy loads into blank fields only.
  • Week selection, actual deload targets and repeatable blocks.
  • Adjustable rest timer with elapsed-time correction on return.
  • Core/stretch library filtered by station equipment.
  • Session notes, during-session response and next-morning check-in.
  • Per-exercise progress, JSON backup/import and CSV export.
  • Home Screen PNG icons, manifest, relative paths and an offline app shell.

Verification and limits

Browser checks covered the 390-pixel and 320-pixel layouts; numeric entry and retention after navigation/reload; separate alternative records; unilateral set entry; partial completion and progress totals; deload rendering; core filtering; and rest-timer extension/dismissal. JavaScript syntax checks and 11 automated tests passed, including data integrity, week boundaries, conservative hinge targets, backup validation/round-trip, legacy preservation, asset references and simulated offline-cache lifecycle.

Not verified on physical iPhone hardware: Safari installation, iOS keyboard behaviour, actual offline launch after HTTPS deployment, VoiceOver operation and background/locked-screen timer behaviour. The preview is HTTP, so service-worker behaviour was tested in isolation rather than as a live installed PWA. No WCAG compliance certification or medical clearance is claimed.

All code, icons and styles are packaged locally. External guidance links need internet access but are not required to train. No programme auto-generation service or cloud database is included. Private records can still be lost if browser data is cleared; use backups.

Recommended later enhancements

After real-world use: add more trainer-verified demonstration media, an explicit equipment inventory, optional rescheduling and a second workout on one day. These should follow actual usage rather than add complexity now. Cloud sync and automatic AI phase generation would require a separate service or publishing bridge; they are deliberately not promised by this free static package.
